# Техническое задание (ТЗ): Сервис регистрации доменов через Dynadot (Telegram Bot + TMA + Web)

## 1. Концепция и цель продукта
Telegram-сервис (ТГ-бот + Telegram Mini App + Веб-интерфейс) для пользователей из РФ и зарубежья, позволяющий быстро (за 5 минут) проверить, выбрать и зарегистрировать международный домен через API Dynadot без ввода паспорта и зарубежных карт (или с оплатой в рублях/крипте). 

**Мультиязычность:** Интерфейс TMA и Telegram-бота поддерживает минимум **два языка: русский (RU) и английский (EN)** с переключением в 1 тап и сохранением языковой преференции в профиле пользователя.

Главный принцип интерфейса: **максимальная простота, интуитивность и минимум текста** для клиентов. Никаких лишних шагов и запутанных меню.

---

## 2. Архитектура и интерфейсы (Гибридный подход)

1. **Telegram-бот:**
   - Входная точка (`/start`), быстрая справка.
   - Уведомления о статусах заказов, напоминания об истечении срока действия доменов.
   - Кнопка запуска Telegram Mini App для подбора и покупки.
2. **Telegram Mini App (TMA):**
   - Основной интерфейс покупки: быстрый поиск, сетка цен, выбор зоны, оплата.
3. **Веб-интерфейс (Личный кабинет + Админ-панель):**
   - Полноценный сайт для работы через браузер (авторизация через Telegram Login).
   - **Админ-панель:** функциональная, но лаконичная и удобная (по аналогии с админкой Job Hunter) — управление наценками по зонам, мониторинг транзакций, логирование API-запросов к Dynadot, ручной перезапуск сбоев и статистика.

---

## 3. Стек технологий и ключевые решения
- **Бэкенд:** Python (FastAPI).
- **База данных:** PostgreSQL (единая БД для пользователей, контактов, доменов, транзакций и логов).
- **Интерфейс TMA / Web:** React + Tailwind CSS (темный minimalist UI в стиле Linear / Vercel).
- **Платежный шлюз:** Аналогично проекту Job Hunter (интеграция с проверенными шлюзами для приема рублей от физлиц в РФ).
- **Интеграция Dynadot API:**
  - Автоматическая проверка доступности и регистрация доменов.
  - Управление NS-серверами (делегирование домена на указанные DNS, например Cloudflare).

---

## 4. Пользовательский сценарий (User Flow)
1. Пользователь запускает бота и открывает TMA.
2. Вводит доменное имя $\rightarrow$ видит доступность по зонам (`.com`, `.net`, `.io` и др.) и цены в рублях (с нашей наценкой).
3. Выбирает домен. **Контактные данные владельца заполняются автоматически** из сохраненного профиля (если покупает впервые — минимальная форма, данные сохраняются для будущих покупок).
4. Оплачивает в 1 клик через платежный виджет (рубли).
5. Бот автоматически отправляет запрос в Dynadot API $\rightarrow$ домен регистрируется $\rightarrow$ пользователю выдается готовый домен с возможностью прописать NS-серверы.

## 5. Открытые вопросы для обсуждения
1. **Платежный провайдер:** Какую платежную систему используем для приема рублей от физлиц (Robokassa, CryptoBot, ЮKassa или агрегатор)?
2. **Хранение данных владельца домена:** Сохраняем ли дефолтный профиль контакта для клиента, чтобы при следующей покупке не вводить данные вообще?
3. **Управление DNS:** Предоставляем ли клиенту простейший редактор DNS-записей (A, CNAME, TXT) внутри TMA или отправляем управлять на NS-серверы Dynadot?
